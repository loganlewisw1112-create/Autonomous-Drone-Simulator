Classroom Mission Simulator

Simulation-only, Windows classroom pilot. The public Vercel Classroom site is a client showcase. A live class requires the local Windows host and relay.

Release boundary: do not use an unsigned engineering package or insecure-LAN override for a graded/live class. The school-pilot release requires trusted HTTPS/WSS, a signed installer, and the real two-machine checklist.

Engineering launch

From an approved checkout using Node 24.x and npm 11.12.1:

npm ci
npm run classroom:desktop

The Electron host starts and owns the relay lifecycle. A terminal-only maintainer can use npm run classroom; the process prints the one-time local administrator token, generated CA certificate path, and approved HTTPS local/LAN addresses. Never publish, log, or send the token to students.

Administration

  1. When Electron owns the relay, enter the first instructor code and confirm its local provisioning dialog. A terminal-owned relay requires its process administrator token.
  2. Keep the administrator token and instructor credential on the instructor machine under the approved Windows account.
  3. The host generates its school-local CA and LAN certificate. Install only the generated public CA certificate on managed student devices; the app does not install Windows trust automatically.
  4. Give students the HTTPS join link or QR containing the pinned instructor-key fingerprint.
  5. Supervise the roster; the class code is not proof of legal identity.
  6. End the class, confirm archive warnings, stop the host, and apply the school retention rule.

Security boundary

Protocol-v3 classroom messages use single-use join capabilities, relay-authoritative timing, and authenticated encrypted application payloads. Approved TLS protects LAN transport. The relay and host still handle connection/routing metadata, and encryption cannot protect a compromised or unlocked endpoint.
